# HPLC Figure Bench

## Purpose and Main Workflows

HPLC Figure Bench is a single-file HTML application for making publication-quality protein purification figures, SDS-PAGE gel figures, SEC calibrations, and summarizing multi-step purification workflows.

It supports two main modes:
*   **Project Mode:** Documents an entire protein purification project across multiple steps (e.g., construct, expression, lysis, chromatography columns, cleavage, final sample). The figure, step timeline, written summary, and methods text build progressively.
*   **Quick-Figure Mode:** A fast, stateless mode (`#quick`) to create publication-ready chromatograms and figures directly from dropped data files without creating a full project.

## How to Open

HPLC Figure Bench runs directly in any modern web browser. Open `hplc-figure-bench(WF1.13).html` locally by double-clicking it or dragging it into a browser window.

## Supported Inputs and Exports

**Inputs:**
*   **Chromatography Data:** `.csv`, `.tsv`, `.txt`, `.zip` (UNICORN 7 result archives), `.asc`, `.dat`, `.arw`, `.xy`, `.json`.
*   **Gel Images:** PNG, JPEG, TIFF (loaded dynamically via `pako` and `UTIF`), or other browser-supported image formats.
*   **Sequences:** GenBank (`.gb`, `.gbk`, `.genbank`, `.ape`, `.dna`) and PDB files (`.cif`, `.mmcif`, `.pdb`, `.ent`).
*   **NanoDrop Readings:** Text and CSV exports.
*   **Project Files:** `.json` project files generated by this tool. Damaged or incomplete entries in a file are skipped, and the app says how many. Spreadsheets (`.xlsx`) and HEIC/PDF pictures are not read; the app asks for CSV or PNG/JPEG/TIFF instead.

**Outputs:**
*   **Figures:** Copy to clipboard as SVG, or save as SVG or PNG (adjustable dpi). Multiple figures can be saved as a ZIP archive.
*   **Data Summaries:** Summary tables, peak integration tables, gel band measurements, and generated methods text exported as CSV or text files.
*   **Project Files:** The complete project state can be exported as a single JSON file.

## Protein mg from the UV area

*   **Formula:** mg = A280 area (mAU·mL) / 1000 / (A280 of 1 mg/mL × UV path in cm).
*   **mAU Traces:** AU traces are shown and integrated in mAU.
*   **Time to Volume Conversion:** Runs exported in minutes are converted to mL using the run's flow rate (read from the file or specified under Flow). If no flow rate is available, no UV mg is reported.
*   **A280 Wavelength:** Only the 280 nm curve yields a calculated protein mass. Other wavelengths (e.g., 260 nm) report area but not mg.
*   **UV Path Length:** When unrecorded in the data file, the app assumes a 2 mm path length (typical ÄKTA monitor). Users can enter custom path lengths on the run card for HPLC flow cells (e.g., 10 mm).
*   **Integration Scope:** Peak and pool areas use the full run after smoothing and baseline correction, so zooming or cropping the plot does not change calculated values.
*   **Pool Volume Calculation:** Calculates volume across pooled fractions from start to end markers, cutting early/late steps according to run log bounds or fraction width medians.

## Gel measurements

*   **Auto Crop & Densitometry:** Automatic and manual cropping of gel images with automated lane finding and densitometry profile integration.
*   **Molecular Weight Estimation:** Estimates band molecular weights using standard protein ladder presets.
*   **Band Tagging & Purity:** Band detection with tagging (target protein, tag, contaminant, known contaminant) and automatic purity percentage calculation across lanes.

* Display dark/light points and color affect the figure, not measured intensities. Invert selects signal polarity.
* In the default area mode, overlapping bands are partitioned without counting rows twice. Hand-added duplicates are checked after snapping. All-stain purity and band percentages share one denominator: the background-corrected signal between the wells and the dye front (the top 3% and bottom 2% of the lane are left out). Removing a band takes it out of that total.
* Cleavage % is molar everywhere (band table, CSV, cleavage panel and Methods): Coomassie stain scales with mass, so each band's area is divided by its mass before comparing cleaved and uncleaved forms.
* When a gel measures the final pool's purity and no QC purity is typed in, the Methods text reports it ("Purity was about 68% by SDS-PAGE.").
* Manual contaminant/exclusion tags override automatic purity estimates. Lane-specific protein marks affect that lane.
* Calibration requires finite marks at distinct positions, with sizes decreasing top to bottom. Invalid marks remain available to correct; derived sizes are withheld.
* Lane edits, processed pixels and ladder positions invalidate the corresponding analysis caches.
* Saturation, manual marks after fine rotation, native image precision, and size-based expression/cleavage inference remain limitations.

## Import and SEC calibration
SEC "Read from run" skips unticked standards, takes peaks in elution order within any entered V0/Vt limits, and asks you to confirm the proposed matching before applying it. If there are fewer peaks than standards, the smallest standards left over are listed and their volumes are cleared, so one fit never mixes two runs. Check peak identities in the proposal. Unrelated peaks inside the limits still need manual review. Superdex 75 and 200 Increase 5/150 columns are distinguished by name; the 75 5/150 bed volume is 3 mL ([Cytiva specifications](https://www.cytivalifesciences.co.jp/catalog/0063.html)).

Tab-delimited UNICORN files support decimal commas. NanoDrop imports treat a lone comma as decimal (0,123 is 0.123), except a comma followed by three digits after a nonzero number (1,234 is 1234). Other grouping commas are removed. Reading timestamps and row positions distinguish replicates when checking for duplicate imports, and readings saved by older versions are matched by name and A280.

## Storage and Backups

*   **Browser Storage:** Uses `localStorage` for user preferences, SEC calibration data, and custom protein entries. Uses `IndexedDB` (`hfb-projects`) to store projects locally in the browser.
*   **Host Integration:** Supports cloud database and asset storage when hosted in an environment providing `window.claude`.
*   **Project Backups:** Export and import complete projects as JSON files for backup or sharing across machines.

## External Libraries and Network Dependencies

The application loads these external resources on demand:
*   **Fonts:** Instrument Sans from Google Fonts (`fonts.googleapis.com` and `fonts.gstatic.com`).
*   **TIFF Gel Support:** `pako` 2.1.0 (`cdnjs.cloudflare.com`) and `UTIF` 3.1.0 (`cdn.jsdelivr.net`) loaded when a TIFF gel image is opened.
*   **PDB Structures:** Structure files loaded from RCSB Protein Data Bank (`files.rcsb.org/download/`) when a PDB code is entered.
